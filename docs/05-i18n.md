# 05 - Words and languages (i18n)

All on-screen text lives in the language files:
- `src/shared/i18n/en.js` - English (the complete set)
- `src/shared/i18n/hi.js` - Hindi (complete)
- `ml.js`, `ta.js`, `te.js`, `ur.js` - Malayalam, Tamil, Telugu, Urdu (what job seekers see; the rest falls back to English, see below)

Rules:
1. **Same keys in both files.** A test (`i18n.test.js`) fails if a key is missing, a kind of value differs, or any text is empty.
2. No words inside components. Use `const { t } = useLang();` then `t.someKey`.
3. Where a name or number goes inside a sentence the value is a small function: `hello: (name) => \`Hello, ${name}\``.
4. Short, plain words. Hindi should be everyday Hindi, not formal.
5. Error messages are plain sentences with no technical words (see `friendlyError.js`; its keys all start with `err`).
6. The chosen language is remembered in the browser (localStorage) and sets `<html lang>`. A first-time visitor whose phone is set to Hindi starts in Hindi (`pickLang.js`).

How to add a word: add the same key to `en.js` and `hi.js`, use it, run `npm test`.

**Open item:** the Hindi was written by an AI. A native speaker should read `hi.js` before launch.

Not translated: text typed by employers (ad titles, company names, cities) and **package names** (typed by the admin; the form reminds them to write Hindi and English, like `30 दिन / 30 Days`).

**Plans and offers (migration 0018):** about 130 new words in `en.js` and `hi.js` (keys for plans: `pkg...`, offers: `offer...`, history: `audit...`, order box: `summary...`, `coupon...`). Coupon problems are shown with the keys `offer_not_found`, `offer_expired` ("Code expired"), `offer_wrong_plan` ("This code is not for this plan"), `offer_already_used` ("Code already used") and the others; the database sends only a short word and the screen picks the sentence in the chosen language. The plain-words example in the offer form is the function `offerPreview`. The Hindi for these words is new and needs the same native-speaker read as the rest.

**Job facts, trust and pages (migration 0020):** about 110 new keys in both files: facts form (`f...`, `exp`), banner and report (`fraud...`, `report...`), counters (`counter...`), footer pages (`about...`, `faq...`, `refund...`, `delete...`), admin (`tabReports`, `deletion...`), page descriptions (`meta...`). The long page texts are lists of `{ h, p }` or `{ q, a }` in `aboutSections`, `faqItems`, `refundSections`. Parts marked `[PLACEHOLDER: ...]` are for the owner to fill after a professional has read them. The Hindi is new and needs a native reader.

**More languages (Malayalam, Tamil, Telugu, Urdu):** `ml.js`, `ta.js`, `te.js` and `ur.js` hold about 240 texts each: everything a job seeker sees (home, jobs list and filters, job page, apply, report, safety banner, alerts, CV maker, agencies, footer, contact, errors). They are **drafts written by an AI** and need a native reader. Anything not in those files **shows in English** (`index.js` fills the gaps from `en.js`): the privacy, terms, FAQ, about, refund and article texts, and the whole employer and admin area. A person chooses a language in the footer (each shown in its own writing); the header button still switches English and Hindi in one tap, and from any other language it goes back to English. Urdu reads right to left (`<html dir="rtl">`). Rules (tested in `i18n.test.js`): a partial file may only use keys that exist in English, with the same kind of value, the same inputs for sentence functions and nothing dropped from them (a missing number or name fails the test). To translate more of a language: add the keys to its file; no other change is needed. The phone's language is used for the first visit when it is one of the six (`pickLang.js`).

**Settings screen (migration 0021):** keys `settingLabel` and `settingHelp` (one entry per setting), `settings...`, `payNotReady`, `aboutWho`.
